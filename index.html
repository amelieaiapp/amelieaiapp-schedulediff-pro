What this app is

ScheduleDiff Pro is an offline desktop tool for comparing two revisions of a construction programme. Its primary job is descriptive: load an earlier file and a later file, and get a structured register of what changed, with the source table and field named for each difference. Schedule health (DCMA 14-point on each revision), exported-float driving path, diagnostics, and optional illustration engines (recomputed CPM, duration-only Monte Carlo) are included. Everything runs on your computer. Nothing is uploaded.

Truth standard: programme facts in the change register and identity sections are quoted from the files you load. Optional CPM and Monte Carlo are network analysis on the loaded file — not a certified forensic delay method and not a substitute for expert analysis. They use ified network rules stated in this help.

Who it is for

Planners, project controls, commercial managers, and reviewers who receive P6, Microsoft Project, or Asta updates and need a clear, defensible account of differences — without turning the tool into a claims engine.

Accepted files

  • Primavera P6 — .xer text export (primary, fully tested path)
  • XML exports — Microsoft Project .xml (MSPDI) and Asta Powerproject XML when exported as XML

Not accepted: native .mpp, native Asta .pp / binary, P6 database connections. Export to XER or XML first.

XML support (honest): MSP XML is tested on real public samples for activities, links, durations, and basic project identity. Asta is supported when the file is XML (often MSP-compatible). Results can be thinner than XER if the export omits float, calendars, or resources. Always check the Review scorecard and diagnostics on your files during the trial.

Other formats are rejected with a clear message. Files never leave this device.

Driving path — plain English

In Primavera, total float is how much an activity can slip before it affects the programme’s required finish (as calculated in P6 and written into the export).

Many tools only look for float = 0 and call that “critical”. That fails on ordinary jobs: if the required completion date sits later than the network’s own calculated finish, every activity can show positive float. Nothing reads zero — and a naive tool reports “no critical path” even though the programme is perfectly normal.

Example you may see: “68h — this programme sits 8.5 days clear of its own datum.”

  • 68 hours is the smallest total float on any activity in that export (assuming an 8-hour day, 68 ÷ 8 ≈ 8.5 days).
  • “Clear of its own datum” means the contractual or required finish is about 8.5 working days later than the finish implied by the network alone. So the tightest activities still have 68 hours of float in the export — they are still the ones driving the outcome.
  • This app therefore uses the minimum float rule: activities holding that minimum are the driving path. That matches expert practice and matches a full CPM check on the Horizon sample (88 activities at minimum float).

CPM engine (optional illustration)

Pro can run a recomputed forward and backward pass using per-activity working-time calendars from the file (work week + exceptions where present in the export), remaining durations, logic, and basic constraints. You will see both:

  • Exported min float (driving path) — taken from the file (P6/MSP/Asta export fields)
  • CPM min float / critical list — recalculated in this app under the rules above

Honest limits: this is not Oracle Primavera. Working time is taken from each activity’s calendar in the file when parseable; if the calendar blob is missing, a simple default week is used and flagged. Project duration is calculated network length — not forced to the plan-finish target date. Use exported dates and floats as the authority for what the programme said; use CPM as a cross-check only.

Monte Carlo (duration uncertainty only)

Durations are sampled with a triangular distribution (±% around remaining duration; default often 30%) and the network is forward-passed many times under the same network rules as the CPM illustration (remaining duration, logic, actual-start locks, early constraints). You get deterministic finish, mean, and percentiles (P10–P95). Typical jobs finish tens of thousands of iterations in well under a second.

This is not a risk register. There are no risk events (weather, permits, interfaces, etc.). It is duration sensitivity only. Deterministic Monte Carlo hours and CPM project hours are calculated under the same rules so they match; they are still illustrative, not a second Oracle schedule.

Diagnostics box

Lists open ends, dangling links (predecessor or successor missing), isolated activities, odd statuses, date-order problems, missing calendars, and parse notes. Severity: error / warn / info. Nothing is left hanging without being recorded.

Records marked for detailed review

After each compare the tool marks the records most worth a closer look (codes CE-01…CE-17): a change that is structural to the programme (logic, constraint, calendar or lag), a scope change, float erosion on a retained activity, out-of-sequence progress, a data-date anomaly, a progress regression, or a change sitting on the driving (minimum-float) path. Every other change is still listed in full; it simply carries no mark.

The mark reflects the type of change and its position in the network only. It is not a severity, not a score, and not a view on cause, responsibility, entitlement, excusability, compensability or quantum — those are for the reviewer to assess. Each marked record cites the exported table, field and values.

How to open and use the JSON file

  1. After compare, click JSON on the util bar. A file like ScheduleDiff_…_verify.json downloads.
  2. Open it in any text editor, VS Code, or a JSON viewer. Or Excel: Data → Get Data → From File → JSON (where available).
  3. You will see: batch reference, compared time, file names, SHA-256/SHA-512 for A and B, activity counts, difference counts by category.
  4. Why keep it: prove which two files were compared, when, and that the hashes still match if you re-hash the original XERs later.
  5. History rows also download a smaller batch-identity JSON if you need to free browser storage.

Monte Carlo — how to use it

This is duration uncertainty only, not a full risk register with risk events. Network rules match the CPM illustration (remaining duration, logic, actual-start locks, early constraints).

  1. Run a normal compare so both programmes load.
  2. On the util bar set MC ±% (default often 30). That is the triangular band around each activity’s remaining duration.
  3. The report shows Deterministic hours (from calendar CPM — same figure as the CPM card) and P10–P95 / Mean from sampling remaining durations on the same calendars.
  4. Runtime: a few thousand iterations on a small network is near-instant. Hundreds of activities × 50,000 iterations can take tens of seconds on this device. Prefer 10–20k while exploring; use 50k for a final pass.
  5. Best practice: use the same ±% when comparing two revisions; treat percentiles as duration sensitivity only — not probable completion under all project risks.
  6. Event-driven risk (weather, permits, interfaces) needs a separate risk tool — not this engine.

CPM engine — what it is

The app can recompute early/late dates from logic for illustration. The primary comparison still quotes exported floats and dates from the files. Use recomputed CPM as a cross-check, not as a substitute for P6’s (or MSP/Asta’s) own schedule calculation. Calendars are simplified relative to full native engines.

Calendars (UK, Gulf, USA, etc.)

Work calendars are read from the programme files (XER CALENDAR table / XML calendar data). The app does not inject a fixed library of Gulf, UK or USA public-holiday calendars. If the contractor’s file carries those calendars, they are compared (name, day hours, week hours, definition fingerprint). Export calendars correctly from P6/MSP/Asta if you need regional rules in the analysis.

What this tool does not do

  • Does not determine cause, responsibility, entitlement, excusability, compensability or quantum
  • Does not implement AACE MIP half-step / progress-versus-re-planning entitlement splits
  • Does not replace a full forensic delay analysis or expert report
  • Does not claim to be Oracle Primavera P6, Microsoft Project, or Asta Powerproject, or to recalculate a schedule exactly as those products would
  • Does not provide a full risk register or risk-event Monte Carlo
  • Does not issue a formal audit opinion — DCMA-style checks here are measured indicators on the export only
  • Does not upload your files or require an account

Primary truthful claim: the change register and related packs report differences found between two programme exports, with provenance. Establishing who caused a change, and whether it is excusable or compensable, is a separate forensic exercise.
